## Auftrag

Implementiere Socket-Authentifizierung/Origin-Prüfung, autorisiertes `room:join`/`room:sync`, Lobby-Verlassen, Präsenz, Chat, die freigegebenen Raum-/Spielereignishüllen, Reconnect-Snapshots und Idempotenz ausschließlich nach `contracts/events.md` und ADR-003. Kein generisches `game:action`.

## Akzeptanzkriterien

- [x] Cookie-/Origin-Auth beim Handshake, Authz und Raummitgliedschaft bei jedem Event; Revocation trennt Sockets
- [x] `room:join` akzeptiert nur `roomId` für bestehende Mitglieder, nie Einladungscode oder erfundene Identität
- [x] Raumversion, flüchtige unversionierte Präsenz und persistente idempotente Chat-Nachrichten folgen getrennten Regeln
- [x] Zwei Browser-Kontexte synchronisieren Raum/Chat/Präsenz; Disconnect verändert keine Mitgliedschaft oder Session
- [x] WebSocket und Long-Polling liefern getestetes `connect_error.data.error` plus HTTP-`ErrorResponse` mit exakt 401/`UNAUTHENTICATED`, 403/`CSRF_REJECTED`, 500/`INTERNAL_ERROR`
- [x] Reconnect/Eventlücke/`VERSION_CONFLICT`/lokale Snapshot-Schemafehler laden Snapshots; alte Acks/Events drehen State nicht zurück
- [x] Unbestätigter Leave wird direkt mit selbem Key wiederholt; exakter Receipt liefert auch nach Austritt nur `{ roomId, roomVersion, closed }` ohne raumbezogene Zusatzdaten
- [x] `room:invitation-rotated` trägt Version/Ablaufzeit, jedoch niemals Code, Hash oder Receipt und erzeugt für Mitglieder keine unnötige Lücke
- [x] Doppelte `clientRequestId` und Live-/Ack-/Snapshot-Duplikate verändern State/Nachrichten nicht doppelt
- [x] Events werden strikt validiert und pro Empfänger projiziert; keine Code-, Secret- oder Privatdaten im Broadcast
- [x] Integrations-/Negativtests für Replays, Parallelität, Lücken, Nichtmitglieder und Revocation
