## Akzeptanzkriterien

- [x] Host erstellt Raum, zweiter Spieler tritt bei
- [x] Fall startet, Katalogbefragung, Hinweis und finale Lösung funktionieren vollständig ohne API-Schlüssel
- [x] Provider-Call-Spy belegt null Aufrufe im Basismodus; alle abschlussrelevanten Inhalte sind per Katalog erreichbar
- [x] Katalogaktionen erzeugen mit Mock- und ohne Provider identische kanonische Hinweise, Phasen und Bewertungen
- [x] Fallback nach Providerfehler oder ungültiger Antwort erzeugt keine doppelten Nachrichten, Hinweise oder Versionserhöhungen
- [x] Reconnect und doppelte Aktion getestet; nach jeder lückenlos angewendeten Eventfolge validiert der lokale Game-Snapshot erneut, terminale Snapshots enthalten `finishedAt`
- [x] Crash-/Recovery-Matrix für `startIntent`: Crash nach Pending-Insert, nach Prepared und nach Room-CAS; identischer Request vollendet, abweichender Request/Payload übernimmt nichts, kein Zwischenstand wird sichtbar/gestartet
- [x] Verlustmatrix nach Prozessneustart: erste Create-/Rotate-Response mit Code, Replay ohne Code/Version; neue Rotation nur mit neuer Request-ID; keine Codes in Receipt/Log/Event
- [x] Join mit identischem Request und altem Code nach Rotation/Ablauf funktioniert nur bei aktueller Mitgliedschaft; ehemaliges Mitglied erhält `NOT_FOUND` statt historischem Snapshot; Leave-Replay nach Austritt enthält nur minimales Ack
- [x] Parallele Joins beweisen atomare Vier-Personen-Grenze/Nichtmitgliedschaft/Version; Handshake-Matrix für WebSocket und Long-Polling deckt `connect_error.data.error`, HTTP Status und Codes ab
- [x] Fremder Raumzugriff und Datenleck-Tests inklusive `room:invitation-rotated` ohne Code/Hash, Receipt-Autorisierung und Lösung erst im terminalen Snapshot
- [x] Modusübergreifendes Sessionbudget: Parallelität bei 59 reserviert genau einen letzten Versuch; Restart/offene Reservierung bleibt gezählt; erfolgreicher Replay/in-flight ruft nicht erneut auf; CAS-/Crash-Ausführung ohne Receipt wird konservativ erneut gezählt; niemals mehr als 60 Versuche
